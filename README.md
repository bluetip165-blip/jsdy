# 다잉 메세지: 소설가의 마지막 문장

iOS·Android 모바일 브라우저에서 설치해 플레이할 수 있는 실시간 온라인 협력 추리 웹앱입니다. 별도의 앱스토어 빌드 없이 HTTPS 주소를 공유하면 함께 입장할 수 있고, AI 소설가 모드는 혼자 즐길 수 있습니다.

## 게임 모드

- **친구와 온라인:** 방장 포함 2~6명. 방장이 대기실에서 참가자를 기다린 뒤 게임을 시작합니다. 방 코드로 입장하고, 실시간 보드와 채팅으로 협력합니다.
- **AI 소설가:** 1인 플레이. 로컬 규칙 기반 AI가 초기 힌트와 라운드별 추가 힌트를 배치합니다.
- **진행 규칙:** 각 영역에 카드 9장과 정답 1장, 초기 명사·형용사 3쌍, 총 3라운드. 라운드마다 오답 6장을 골라 제거하고, 실패할 때마다 추리 타일(목숨) 1개를 잃습니다. 최종에는 오답 6장을 제외해 정답 3장을 남기며, 최대 4회 도전합니다.
- 온라인 방과 플레이어 토큰은 서버의 `DATA_DIR`에 저장됩니다. 연결이 끊기거나 새로고침해도 같은 브라우저의 재접속 토큰으로 돌아올 수 있습니다.

## 로컬 실행

Node.js 20 이상에서:

```sh
npm ci
npm start
```

기본 주소는 `http://localhost:3000`입니다. 개발 PC와 같은 네트워크 안에서 모바일로 접속할 때는 PC의 로컬 IP 주소와 포트 3000을 사용하세요. 이 방식은 로컬 시연용이며, 외부 친구와 공유하려면 공개 HTTPS/WSS 배포가 필요합니다.

## Docker 배포

```sh
docker build -t dying-message .
docker run --name dying-message -p 3000:3000 -v dying-message-data:/data dying-message
```

호스팅에서는 Dockerfile을 배포하고, 호스트가 지정하는 `PORT`를 사용하도록 두세요. `/data`에 **영구 볼륨**을 연결해야 재시작 후 방 데이터가 유지됩니다. WebSocket을 지원하는 단일 인스턴스로 시작하고 HTTPS를 활성화하세요. 여러 서버 인스턴스를 동시에 운영하면 현재의 인메모리 실시간 방 동기화가 공유되지 않으므로 Redis/공유 세션 계층 추가가 필요합니다.

## 모바일 설치

공개 HTTPS 주소를 iOS Safari에서 열고 **공유 → 홈 화면에 추가**, Android Chrome에서는 **앱 설치** 또는 **홈 화면에 추가**를 선택하세요. 앱 셸은 오프라인 캐시되지만, 멀티플레이/신규 방 생성에는 인터넷 연결이 필요합니다.

## 호스팅과 공개 URL

소스는 Docker를 지원하는 Node 호스팅에 배포할 수 있게 준비되어 있습니다. 공개 URL을 실제로 발급하려면 배포 대상 계정/프로젝트와 도메인이 필요합니다. 호스팅 플랫폼을 알려주시면 그 환경에 맞춰 배포 설정과 연결을 진행할 수 있습니다.

## 콘텐츠 범위 및 권리

현재 빌드에는 사용자가 전달한 규칙 설명과 사진에서 확인된 예시를 바탕으로 구성한 플레이 가능한 카드 이름·타일 목록, 자체 UI 그래픽이 포함됩니다. 원본 제품의 카드 23/23/9장 전체 문구·삽화가 모두 제공된 것은 아니므로 원본 구성물과 카드 데이터가 완전히 동일하다고 보장하지 않습니다. 원본의 전체 콘텐츠/브랜드/삽화를 공개 배포에 사용하려면 권리자의 공유·디지털 이용 허가와 전체 카드 데이터가 필요합니다. 현재 목록은 `server.js`의 `catalog`에서 관리합니다.
